# Cypher Rants — design spec (v3)

Mockups (private canvas, owner only): https://claude.ai/artifact/HUjCp1nCUqBLWC5bAucMP9 (eleven boards: home empty / with posts / light, article, about + cast, mobile, component sheet, doodle system people, doodle system things + marks, doodles in use, squiggle levels). Every doodle on those boards was generated by `tools/doodle.py`; the sheets are the reference for what exists, this file is the reference for how to build it.

## Stack constraints

Jekyll on GitHub Pages, built from `main` at the repo root. Plain HTML, CSS, vanilla JS. No build step for doodles at runtime: they are static SVG (or images) checked into `assets/`. Keep dependencies, previews and generated output out of Git.

## Structure: a notebook, not a landing page

Every page is a fixed left rail plus the page. There is no top nav and no footer.

- `.shell` is `display: flex`. `.rail` is 300px, sticky, `border-right: 1.5px solid var(--line)`, padding `44px 34px`. `.main` is `flex: 1`, padding `52px 64px`. Below 900px the rail collapses to a top strip (portrait 40px + wordmark + theme toggle + menu button revealing the nav); no sidebar.
- Rail contents, top to bottom: portrait doodle (150px, on a wash blob), wordmark (`.mark` "cr." + "cypher rants"), one-line intro (muted, 13.5px), nav list (`writing / about / cast` — the active item is prefixed with a pen-coloured hand-drawn arrow SVG, the others indented to match), theme toggle (sketch border), then pushed to the bottom: `github ↗ / x ↗` and the © line. An Atom feed lives at `/feed.xml` (linked in `<head>`, not in the nav).
- Every page opens with a `.rule`: a `.mark` label on the left ("the writing", "about", "the cast"), muted meta on the right ("N posts · newest first"), hairline underneath.

## Type, grain, devices

- Patrick Hand for the page text (body 18px/1.55, prose 19px, headings at weight 400), Caveat 500 for the annotation hand (margin notes, figure captions, cast names, speech bubbles), IBM Plex Mono for typed details only (code, dates, meta, chips, stamps, the `cr.` mark). Google Fonts css2 with `display=swap`. Lowercase UI labels.
- Paper grain on both themes: `body::after`, `position: fixed`, full viewport, `pointer-events: none`, background = inline SVG data URI with `feTurbulence type="fractalNoise" baseFrequency="0.82" numOctaves="3" stitchTiles="stitch"` + `feColorMatrix type="saturate" values="0"`, `mix-blend-mode: overlay`, opacity ~.35.
- The five ink devices (reuse, do not invent more):
  1. `.mark` — inverted box: `background: var(--mark-bg); color: var(--mark-fg); padding: 0 .3em; box-decoration-break: clone`. Used on section labels, post h2s, the "cr." brand mark (rotated −3°).
  2. `.hl` — highlighter: `background: var(--pen-hl); border-radius: 3px 7px 4px 6px; box-decoration-break: clone`. Sparingly, in prose and on the status word in post meta.
  3. `.sketch` — hand-drawn border: `border: 1.5px solid; border-radius: 255px 15px 225px 15px / 15px 225px 15px 255px`. Theme toggle, chips, cards; code blocks use the softer `3px 9px 4px 8px`.
  4. Scribble underline under the active nav item: inline SVG 64×8, path `M1 5c10-3 20 2 31-1s20 1 31-2`, stroke `var(--pen)`, width 2, round caps.
  5. `.hand` — Caveat ~24px in `var(--pen)`, plus a small pen-drawn arrow SVG. Margin notes and the empty state only.
- Colour rules: ink for structure, `--pen` only for what the paragraph is about, `--red` only for "no", `--green` only for "yes". Washes never on lines. No gradients, shadows or glow. Contrast ≥ 4.5:1 for text (the muted values above already pass on both papers).

## Components

- Post card (`index.html`): `.card` with sketch border, padding `24px 26px 20px 116px`, min-height 156px, alternating `rotate(-.4deg)` / `rotate(.4deg)` via `:nth-child`. The cover doodle (112px) is absolutely positioned at `left: -10px; top: -18px`. Inside: `time` 12px muted, `h3` 21px/600, description 14px muted, `.chips` (sketch border, 11px; "draft" in pen). A dashed `.card.ghost` ("drop a .md into _posts/ and it shows up here") always sits last. With zero posts it is preceded by the Alice/Bob empty-state figure (two faces, two bubbles, one long pen arrow labelled "any update?", a "0 posts" stamp).
- Cast strip: `_includes/cast-strip.html` — `.rule` "the cast" + a row of 96px doodles with names in 13px mono. Home bottom and about page.
- Article (`_layouts/post.html`): top "← all writing" in pen. Header and body are a 2-column grid, `640px + 240px`, column gap 44px. Header: meta line (date · optional `.hl` status · read time), h1 54px/600 −.04em, description; cover doodle 150px in the right column with a Caveat caption. Prose: h2 wrapped in `.mark`, inline code on `var(--code)`, pre with the soft sketch radius, blockquote with a 3px pen rule in italic muted, links in pen. End of post: hairline, "← previous rant" / written-by card (56px portrait + name) / "next rant →".
- About (`about.md`): `.rule` "about", 2-col: text (h1 "Behind the rants.", existing copy, github/x as pen chips) + 220px portrait with a Caveat caption; then `.rule` "the cast" + 5-up grid of 170px doodles, Caveat name, muted role line.
- Ship `/components.html` (excluded from nav, `noindex`) rendering every component so changes can be eyeballed.

## Markdown conventions the layouts must support

1. Margin note: a paragraph ending with `{:.aside}` (kramdown IAL) moves to the margin column, Caveat, pen colour, aligned with the previous paragraph. Hidden (or folded inline) below 900px.
2. Dialogue: a fenced block ` ```dialogue ` with lines `alice: …` / `bob: …` renders as `.dlg` turns — face 72px + `.bubble` with a hand-drawn tail SVG, alternating sides. Implement with a Liquid include over captured text or a kramdown block IAL + a tiny JS transform, whichever keeps authoring closest to plain text.
3. Margin reaction: `{% include react.html who="bob" say="three? that's it?" %}` — 96px face + mini bubble in the margin. One per screen, never more.
4. Figure: `{% include figure.html src=… caption=… %}` spans both columns (`grid-column: 1 / -1`, hairlines above and below, Caveat caption "fig. n — …"). Scenes are just images you draw; the include only frames them.
5. Sticky note: a blockquote whose first word is `note:` renders as `.note` (ochre wash, `rotate(-1.2deg)`, Caveat "note" label). Ordinary blockquotes keep the pen rule.
6. Inline glyphs: `:key:`, `:envelope:`, `:alice:` … are swapped by an include for the style-1 (glyph) SVG at 18–22px, `vertical-align: -4px`. Faces too.

## Doodle system

`tools/doodle.py` is the drawing engine (Python, no dependencies). It produces SVG strings; run it once to generate the assets, do not ship it to the browser.

- `Pen(seed, style, rough)`. `style` 1–6: glyph · line · wash · pencil · ink · cut-paper. `rough` 0–3.6: 0 ruler, 0.3 steady, 0.6 careful, 1 default, 1.4 quick, 2 shaky, 2.8 rattled, 3.6 caffeine. Same seed = same drawing, so a character is reproducible.
- `face(pen, head, skin, hair_, hair_color, eye, brow, nose_, mouth_, fh, extra, wash, back, look)` — 8 heads, 9 skin tones, 31 hair/headwear, 17 eyes, 8 brows, 8 noses, 13 mouths, 8 facial hair, 20 accessories/marks, 8 backings (blob, blob2, square, tall, ring, hatch, scribble, none). See the people sheet for every option by name.
- `obj(pen, kind, wash)` — 66 things (envelope … question). See the things sheet.
- Connectors and marks: `arrow` (curve, dashed, both, head), `lightning`, `bubble` (round / rect / spiky / thought; pass `to=(x, y)` — the speaker's chin — and the tail is aimed at it, otherwise a fixed tail bl br l r tl), `text`, `stamp`, `pin_num`, `tape`, `circle_emph`, `crossout`, `underline_scribble`, `bracket`, `sparkles`, `paperclip`, `tack`. Scenes are composed with `place(inner, x, y, scale)` inside one `<svg>`.
- Roughness rules: 0–0.6 when the drawing carries information (stacks, sequences, tables); 1 is the house hand; 1.4–2 for emotion, following the character's state; 2.8+ once per post; never mix levels inside one figure; text is never rough.
- Style rules: glyph for inline and ≤32px; line at 48px; wash from 72px up (the blog default); ink and cut-paper for covers and large figures; keep one level per page.

Data:

- `_data/cast.yml`: one entry per character — `name`, `role`, and the `face()` recipe (`head, skin, hair, hair_color, eye, brow, nose, mouth, fh, extra, wash, back`). The reference cast is the classic crypto placeholders (alice, bob, carol, dave, eve, mallory, trent, peggy, victor, walter, oscar, sybil, grace, heidi, ivan, judy, frank, erin, chuck, craig, faythe, olivia, wendy, pat), drawn as diverse people with one distinctive thing each; rename or drop freely.
- Generated assets land in `assets/doodles/<name>.svg` (people and things) via a small script in `tools/` that reads `cast.yml` and calls the engine. Commit the SVGs, not the build.
- Post front matter: `cover: bob` picks the card/article doodle (default: author); `rough: 2` overrides the hand for that post's cover.

## Guardrails

Both themes, 390px mobile, and a post that uses every convention above. Do not invent posts or characters beyond `cast.yml`; placeholders stay bracketed. Do not display an email or add a contact form. GPG-sign commits.

Rule for every bubble, SVG or HTML: the tail is the plain wedge from the first mockups — its fill laid over the outline, only its two sides stroked — and it points at the speaker's face. In the engine `to=(x, y)` puts the wedge on the edge nearest that point and aims the tip at it (short, slightly slanted); otherwise `tail` picks a fixed corner. In the page `_includes/tail.html` is the same wedge; HTML bubbles use a mild border radius so the wedge's base always sits on a straight edge (the sketch radius bends the edge through the wedge). Dialogue tails sit at the bubble's vertical centre beside the face, margin-reaction tails are centred under the face.
